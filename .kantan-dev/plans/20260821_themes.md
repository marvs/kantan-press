## Conventions this plan follows

There is no `AGENTS.md` or `CLAUDE.md` in the repo, so conventions are taken from the
existing code and the README:

- `rubocop-rails-omakase`; service objects under `app/services/<namespace>/` with a
  `.call` entry point, as `Wordpress::*` does.
- RSpec: request specs for controllers, service specs for services, `factory_bot`
  factories, shared helpers in `spec/support/`.
- **No JavaScript build step.** Propshaft plus importmap; theme JS is served as a plain
  file and must never enter the importmap.
- Configuration reads ENV first, then credentials, via `KantanPress::Config`.
- `bundle exec rspec`, `bundle exec rubocop` and `bundle exec brakeman` all stay green.

## Design

### The filesystem owns theme content; the database owns only the choice

A theme is a **directory**. Built-in themes ship in the repo at `themes/<slug>/`;
uploaded themes are extracted to `storage/themes/<slug>/`, which Kamal already persists
via the `kantan_press_storage:/rails/storage` volume. Both are read by the same code, so
there is one code path rather than two.

The `themes` table stores only *which* theme is active and *what its settings are*. Theme
files are never written to the database. Uninstalling is deleting a directory and a row.

```
themes/independent/                 built-in, in the repo
storage/themes/<slug>/              uploaded, on the persisted volume
├── theme.json                      manifest + settings schema
├── screenshot.png
├── assets/
│   ├── theme.css
│   ├── theme.js
│   └── fonts/*.woff2
└── templates/
    ├── layout.liquid
    ├── index.liquid
    ├── post.liquid
    ├── page.liquid
    └── archive.liquid
```

### Escaping rule (security boundary)

Liquid does **not** auto-escape, and Jekyll/Shopify convention is for the theme author to
write `| escape`. That is the wrong default here, because a theme that forgets it turns an
imported WordPress title into stored XSS.

So: **drops return already-escaped text; raw HTML is only ever exposed through an
explicitly named `*_html` field.** `{{ post.title }}` is safe; `{{ post.body_html }}` is
deliberately raw and carries the author's own block markup, exactly as
`render_post_body` does today. Comment bodies pass through Rails `sanitize` because they
are the one field that came from the public. This must be documented in the theme API doc
so authors do not add a redundant `| escape`.

### Rendering never takes the site down

Theme rendering is wrapped so a broken template cannot 500 the public site. On
`Liquid::Error` or a missing template: raise in development and test, and in production
log the error and fall back to the **existing ERB views**, which stay in place unchanged.
This makes the whole feature additive and gives a working escape hatch.

### Non-goals

- **Gutenberg editor styling stays independent of the theme.** Confirmed by the user. The
  editor keeps its current styles; no theme CSS is injected into the editor canvas.
- Sidebar/widget areas. Explicitly deferred in the IDEA.
- Theme marketplace, updates, or version checks.

## Tasks

### 1. Add dependencies and write the theme package format doc

- `Gemfile` — add `gem "liquid", "~> 5.5"` and `gem "rubyzip", "~> 2.3", require: "zip"`.
- `docs/THEMES.md` (new) — the theme author contract: directory layout, `theme.json`
  schema, the template list, every drop and its fields, available filters, the escaping
  rule above, and the asset-path convention.

**Verify:** `bundle install` succeeds; `bundle exec rubocop`; `bundle exec bundler-audit`.

### 2. `Themes::Bundle` — one theme directory as a value object

- `app/services/themes/bundle.rb` — wraps a root path. Exposes `slug`, `name`, `version`,
  `author`, `author_url`, `source` (`:builtin` / `:uploaded`), `manifest`,
  `settings_schema`, `template(name)`, `asset_path(relative)`, `screenshot?`, `valid?`.
- Manifest parsing rejects an unknown `kantan_theme_api`, a slug not matching
  `/\A[a-z0-9][a-z0-9-]*\z/`, and a slug that does not match the directory name.
- `asset_path` resolves the real path and asserts it is inside the bundle root — this is
  the single chokepoint for traversal defence, used by both the asset controller and the
  installer.

**Verify:** `spec/services/themes/bundle_spec.rb` — valid manifest, missing `theme.json`,
malformed JSON, bad API version, slug mismatch, `asset_path` rejecting `..`, an absolute
path, and a symlink pointing outside the root.

### 3. `Themes::Registry` — discovery

- `app/services/themes/registry.rb` — `all`, `find(slug)`, `default` (slug
  `independent`), `builtin_root`, `uploaded_root`. Scans both roots, skips invalid
  bundles with a logged warning rather than raising, and gives built-ins precedence on a
  slug collision.

**Verify:** `spec/services/themes/registry_spec.rb` — discovers built-in and uploaded,
skips a broken directory, built-in wins a slug collision, `default` always resolves.

### 4. `Theme` model and migration

- Migration `create_themes` — `slug` (unique index), `active` (boolean, default false,
  not null), `settings` (json, default `{}`, not null), timestamps. A unique partial index
  on `active WHERE active` enforces one active theme at the database level.
- `app/models/theme.rb` — `bundle` (delegates to the registry), `activate!` (transaction,
  deactivates others), `settings_with_defaults` (schema defaults merged under stored
  overrides), and validation of `settings` against the bundle's schema: unknown keys
  rejected, `select` values must be in `options`, `color` must match `/\A#\h{6}\z/`,
  `boolean` coerced.
- Class methods `Theme.active_bundle` and `Theme.active_settings`, both falling back to
  `Registry.default` and schema defaults when no row exists, so a fresh database renders
  with no seed step.
- `spec/factories/themes.rb`.

**Verify:** `spec/models/theme_spec.rb` — single-active invariant survives concurrent
activation, settings merge, each schema validation rule, fallback with an empty table.

### 5. Liquid drops

- `app/services/themes/drops/` — `SiteDrop`, `PostDrop`, `CategoryDrop`, `TagDrop`,
  `MediaItemDrop`, `CommentDrop`, `PaginationDrop`, `SettingsDrop`.
- Drops are the allow-list: only declared methods are reachable, so a theme cannot walk
  from a post to `User#password_digest` or to `KantanPress::Config`.
- `PostDrop` covers `title`, `url`, `excerpt`, `body_html`, `published_at`, `word_count`,
  `author_name`, `categories`, `tags`, `featured_image`, `comments`. Escaping follows the
  rule in Design.
- `word_count` is needed by the default theme's cover meta; derive it from the stripped
  body.

**Verify:** `spec/services/themes/drops_spec.rb` — every field, HTML in a title comes back
escaped, `body_html` comes back raw, comment content is sanitized, an undeclared method
returns nil rather than invoking it.

### 6. `Themes::Renderer` and custom filters

- `app/services/themes/renderer.rb` — `Themes::Renderer.call(bundle:, template:,
  assigns:, settings:)`. Parses with a cached `Liquid::Template` per (bundle, template,
  mtime), renders the inner template, then renders `layout.liquid` with
  `content_for_layout`.
- Resource limits set explicitly (`render_length_limit`, `render_score_limit`,
  `assign_score_limit`) so a hostile or accidental infinite theme cannot exhaust the box.
- `app/services/themes/filters.rb` — `asset_url` (maps `'theme.css'` to the theme asset
  route, with a cache-busting digest), `post_url`, `category_url`, `tag_url`,
  `archive_url`. Liquid's own `date`, `escape`, `strip_html`, `truncate` cover the rest.

**Verify:** `spec/services/themes/renderer_spec.rb` — renders through the layout, template
cache invalidates on mtime change, resource limits abort a runaway loop, filters produce
correct URLs, `Liquid::Error` propagates in test env.

### 7. Public site renders through the active theme

- `app/controllers/concerns/themed_rendering.rb` — `render_theme(template, **assigns)`:
  resolves the active bundle and settings, renders, and `render html: ..., layout: false`.
  Rescues `Liquid::Error` / missing template → re-raise in dev and test, log and
  `render <erb_template>` in production.
- Wire into `PostsController#index` / `#show`, `CategoriesController#show`,
  `TagsController#show`, `ArchivesController#show`. `#show` picks `page.liquid` when
  `post_type` is `page`, else `post.liquid`.
- Existing ERB views and `application.css` are left untouched as the fallback path.
- The Atom feed and all of `/admin` are unaffected.

**Verify:** `spec/requests/themes_spec.rb` — each public page renders through the theme;
markup from the theme is present and the old ERB markup is not; a deliberately broken
theme falls back to ERB with `Rails.env.production?` stubbed; the feed is untouched.
Existing `spec/requests/public_site_spec.rb` and `block_rendering_spec.rb` must still pass
(update expectations where the theme legitimately changes markup).

### 8. Serve theme assets

- Route, declared **above** the public section in `config/routes.rb` so neither `/:slug`
  nor the `*path` catch-all can shadow it:
  `get "themes/:slug/assets/*path", to: "theme_assets#show", as: :theme_asset,
   constraints: { slug: /[a-z0-9\-]+/ }, format: false`.
- `app/controllers/theme_assets_controller.rb` — `allow_unauthenticated_access`, resolves
  through `Bundle#asset_path`, allow-lists extensions
  (`css js woff2 woff ttf otf png jpg jpeg gif svg webp ico`), `send_file` with the right
  content type and `Cache-Control: public, max-age=31536000, immutable`, 404 otherwise.
  Thruster turns `send_file` into X-Sendfile in production.

**Verify:** `spec/requests/theme_assets_spec.rb` — serves CSS and a woff2 with correct
type and cache header; 404s on `..%2f`, an encoded absolute path, a symlink out of the
root, a disallowed extension (`.rb`, `.liquid`, `.json`), and an unknown slug. Confirm
`bundle exec brakeman` reports no `send_file` warning.

### 9. `Themes::Installer` — zip import

- `app/services/themes/installer.rb` — `Themes::Installer.call(uploaded_file)` returning a
  result object with the bundle or an error list.
- Defences, all covered by specs:
  - upload size cap (10 MB) and **uncompressed** total cap (50 MB) plus an entry-count cap
    — zip-bomb defence, since a compressed size check alone does not catch one;
  - reject entries with `..`, an absolute path, or a symlink;
  - allow-list entry extensions (asset list above, plus `json liquid md txt`);
  - tolerate a GitHub-style single wrapper directory;
  - require a valid `theme.json` and reject a slug that collides with a built-in.
- Extract to a temp dir, validate the assembled bundle, then move atomically into
  `storage/themes/<slug>`; replace an existing upload of the same slug only on an explicit
  overwrite flag.

**Verify:** `spec/services/themes/installer_spec.rb` — happy path, wrapper directory,
traversal entry, symlink entry, zip bomb, oversize upload, missing manifest, bad manifest,
built-in slug collision, disallowed extension, and that a failed install leaves
`storage/themes` untouched.

### 12. Build the default theme package

`themes/independent/` — the values are recorded in the IDEA's *Reference measurements*
section and should be taken from there.

- `theme.json` — name "Independent", `kantan_theme_api: 1`, and the four settings the user
  chose: `accent_color` (color, default `#57ad68`), `cover_height` (select:
  short/medium/tall, default medium), `show_word_count` (boolean, default true),
  `body_font` (select: serif/sans, default serif).
- `assets/fonts/` — PT Sans and PT Serif, 400/700 plus italics, as woff2. Both are OFL,
  so redistribution is fine; include the OFL text as `assets/fonts/LICENSE`.
- `assets/theme.css` — `@font-face` blocks pointing at those files; the cover image block
  (`padding: 25vh 0 30px`, the `linear-gradient(rgba(0,0,0,.1) 50%, rgba(0,0,0,.65))`
  scrim, `background-size: cover`, `background-attachment: scroll`); the title at
  `2.625rem` white with `text-shadow: 0 1px 3px rgba(0,0,0,.8)`; the meta line at
  `rgba(255,255,255,.73)`; body copy in PT Serif `1.063rem`, UI in PT Sans `1.1875rem`
  `line-height: 1.55`, ink `#383838`. Settings arrive as CSS custom properties written
  into a `<style>` block by `layout.liquid`.
- **The WordPress block styles in `application.css` (`.post-body .wp-block-*`) must be
  carried into the theme's content styles**, or imported posts lose their layout. This is
  the largest piece of CSS to move and is easy to overlook.
- `assets/theme.js` — the scroll fade, in plain vanilla JS with no jQuery, loaded via a
  plain `<script defer>` and **not** through importmap. Fades `.cover-meta`, not the
  image, matching the reference:
  `meta.style.opacity = Math.max(0, 1 - window.scrollY / cover.offsetHeight)`, bound to
  `scroll` (passive) and `resize`, throttled with `requestAnimationFrame`, and run once on
  load.
- `templates/layout.liquid`, `post.liquid`, `page.liquid`, `index.liquid`,
  `archive.liquid`. The cover's `background-image` is per-post, so it is an inline style
  on the element, as the reference does it.
- `screenshot.png`.

**Verify:** `spec/requests/themes_spec.rb` gains cases for the cover block rendering with
the featured image URL, the title inside the cover, the meta line, word count honouring
its setting, and a post with **no** featured image degrading to a titled header rather
than an empty black band.

## Risks

| Risk | Mitigation |
|---|---|
| Zip upload is a file-write path reachable from the browser | Task 9's caps and allow-lists; extraction to a temp dir with an atomic move; specs for traversal, symlinks and bombs |
| A broken theme takes the public site down | ERB fallback in production (task 7) |
| Theme asset route shadowed by the existing `/:slug` and `*path` catch-alls | Route declared above them; explicit request specs |
| Imported WordPress posts lose their block layout | Task 12 explicitly carries `.wp-block-*` styles into the theme |
| Liquid's no-auto-escape default causing stored XSS | Escaped-by-default drops with named `*_html` fields; documented in `docs/THEMES.md` |
